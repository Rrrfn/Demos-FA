# قیمت‌یار — ربات تلگرام پایش بازار

ربات تلگرام پایش بازار: قیمت لحظه‌ای طلا، سکه، ارز و رمزارز از منابع واقعی، سیستم هشدار با
شرط‌های قابل‌تعریف، تاریخچهٔ قیمت و رابط کاملاً فارسی. ساخته‌شده با **aiogram 3**، **aiohttp**
و **SQLite**.

هیچ قیمتی در کد ثابت نیست. هر عددی که به کاربر نشان داده می‌شود از یک منبع زندهٔ بیرونی
می‌آید و اگر منبع در دسترس نباشد، ربات صریحاً همین را می‌گوید.

> **توجه:** این پروژه یک نمونه‌کار نمایشی است و قیمت‌های آن جنبهٔ راهنما دارد، نه توصیهٔ
> معاملاتی. برای معاملهٔ واقعی از منبع رسمی استفاده کنید.

---

## اجرای محلی

نیازمندی: Python 3.10 یا بالاتر.

```bash
cd 05-ghematyar-bot
python -m venv .venv
source .venv/bin/activate        # ویندوز: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env             # و TELEGRAM_TOKEN را داخل آن بگذارید
```

پیش از هر چیز، سلامت منابع داده را **بدون نیاز به توکن تلگرام** بسنجید:

```bash
python -m ghematyar check
```

خروجی نمونه (اجرای واقعی همین پروژه):

```
موفق: 25/25

وضعیت منابع:
  🟢 coingecko: 11 قلم (753ms)
  🟢 tgju: 14 قلم (1675ms)
```

سپس ربات را در حالت توسعه (polling) اجرا کنید:

```bash
python -m ghematyar            # یا: python -m ghematyar polling
```

ساخت دستی پایگاه داده:

```bash
python -m ghematyar init-db
```

### حالت‌های خط فرمان

| فرمان | کار |
|---|---|
| `python -m ghematyar` | اجرای ربات با long polling (توسعهٔ محلی) |
| `python -m ghematyar webhook` | اجرای وب‌سرور aiohttp برای تولید |
| `python -m ghematyar check` | آزمون زندهٔ منابع داده، بدون توکن |
| `python -m ghematyar init-db` | ساخت پایگاه داده و نمایش خلاصه |
| `python -m ghematyar --help` | راهنما |

## دستورهای ربات

| دستور | کار |
|---|---|
| `/start` | شروع و منوی اصلی |
| `/help` | راهنما |
| `/market` | نمای کلی بازار (اقلام شاخص هر دسته) |
| `/price` | قیمت یک قلم؛ بدون آرگومان، فهرست شاخص‌ها |
| `/gold` `/coins` `/crypto` `/currency` | نمای یک دسته |
| `/chart` | نمودار تاریخچهٔ ثبت‌شده |
| `/alert` | ساخت هشدار (مرحله‌به‌مرحله یا با یک جمله) |
| `/alerts` | فهرست و مدیریت هشدارها (توقف، فعال‌سازی، حذف) |
| `/events` | گزارش رویدادها: چه شد و چرا اعلانی نیامد |
| `/watchlist` | دیده‌بان کاربر |
| `/status` | وضعیت منابع داده، کش و تاریخچه |
| `/about` | دربارهٔ داده‌ها و سلب‌مسئولیت |

**متن آزاد** هم پشتیبانی می‌شود: «قیمت دلار چنده؟» قیمت را می‌دهد، «دلار بالای ۲۵۰۰۰۰» هشدار
می‌سازد، و «دلار بالای» (بدون عدد) عدد را می‌پرسد. هر سه حالت فارسی محاوره‌ای را می‌فهمند.

۲۵ قلم در چهار دسته:

| دسته | تعداد | اقلام |
|---|---|---|
| طلا | ۳ | طلای ۱۸ و ۲۴ عیار، مثقال طلا |
| سکه | ۵ | سکه امامی، بهار آزادی، نیم‌سکه، ربع‌سکه، سکه گرمی |
| ارز | ۶ | دلار، یورو، پوند، درهم، لیر ترکیه، یوان |

تاریخچه و هشدار) از همان رجیستری تغذیه می‌شوند.

## قابلیت‌ها

- **قیمت زنده** برای ۲۵ قلم، با نمایش قیمت، تغییر مطلق و درصدی، زمان آخرین داده و نام منبع
- **جستجوی فارسی**: نام فارسی، نام لاتین و مترادف‌های رایج
- **هشدار قیمت** با شرط بالا/پایین رفتن از آستانه؛ ساخت با یک جمله یا مرحله‌به‌مرحله
- **پایش پس‌زمینه**: بررسی دوره‌ای هشدارها و اعلان در صورت برقرارشدن شرط
- **تاریخچهٔ قیمت** و رسم نمودار از داده‌های واقعاً ثبت‌شده
- **دیده‌بان** با قیمت تازه برای هر کارت
- **گزارش رویداد** برای پاسخ به «چرا اعلان نگرفتم؟»
- **وضعیت منابع** با تأخیر پاسخ و مقدار کش
- **مقاومت در برابر خطای شبکه**: مهلت زمانی، تلاش مجدد با تأخیر نمایی، مدارشکن و تشخیص کهنگی

مدیریت هشدار شامل جلوگیری از تکرار، سقف تعداد برای هر کاربر، فاصلهٔ زمانی حداقل بین دو اعلان
یک قلم، سقف اعلان ساعتی، حالت یک‌بارمصرف یا تکرارشونده، وضعیت فعال/متوقف و غیرفعال‌سازی
خودکار پس از خطاهای مکرر ارسال است.

import کردن پکیج هیچ عارضهٔ جانبی ندارد: نه پایگاه داده ساخته می‌شود، نه به شبکه می‌رود و نه
توکن لازم است. همه‌چیز داخل `build_services` و `build_runtime` ساخته می‌شود؛ همین باعث می‌شود
برنامه در یک پروسه چند بار قابل ساخت باشد (تست‌ها، وب‌سرور، جابه‌جایی بین polling و webhook)
و هندلرها به وضعیت import وابسته نباشند.

## منابع داده و رفتار دادهٔ زنده

| منبع | پوشش | وضعیت |
|---|---|---|
| `tgju.org` (خوراک ماشین‌خوان) | طلا، سکه، ارز — ۱۴ قلم | منبع اصلی بازار داخلی |
| صفحهٔ HTML همان منبع | فقط «سکه گرمی» که در خوراک ماشین‌خوان نیست | آخرین راه |
| `api.coingecko.com` | رمزارز — ۱۱ قلم، همراه تغییر ۲۴ ساعته | منبع مستقل رمزارز |

انتخاب منابع پیش از پیاده‌سازی بررسی شد: دسترس‌پذیری، ساختار پاسخ، محدودیت نرخ و رفتار در
خطا. دو نکته که در عمل دیده شد:

- خوراک ماشین‌خوان رمزارزها **دلاری** است ولی صفحهٔ HTML همان منبع، تتر را **تومانی** نشان
  می‌دهد. یک قلم با دو واحد در دو مسیر، خطرناک‌تر از نبود داده است؛ بنابراین رمزارزها عامدانه
  از مسیر HTML کنار گذاشته شده‌اند.
- رمزارزها از یک منبع مستقل خوانده می‌شوند تا قطعی یک منبع، کل دسته را از کار نیندازد.

قواعد غیرقابل‌مذاکرهٔ لایهٔ نمایش:

1. **هیچ قیمت ثابت یا ساختگی وجود ندارد.** اگر هیچ منبعی داده ندهد، ربات صریحاً می‌گوید داده
   در دسترس نیست.
2. **کش کوتاه‌مدت، ولی برچسب‌دار.** پاسخ‌های پشت‌سرهم از کش سرو می‌شوند (پیش‌فرض ۶۰ ثانیه) و
   نمایش می‌دهد که از کش آمده است.
3. **سن داده همیشه دیده می‌شود:** «لحظه‌ای پیش»، «۳ دقیقه پیش» و مانند آن.
4. **کهنه با برچسب، منقضی هرگز.** قدیمی‌تر از آستانهٔ کهنگی علامت می‌خورد و قدیمی‌تر از آستانهٔ
   انقضا به هیچ عنوان نمایش داده نمی‌شود.
5. **تغییر از تاریخچهٔ خودمان.** درصد تغییر فقط وقتی نمایش داده می‌شود که یک مشاهدهٔ ثبت‌شدهٔ
   قبلی وجود داشته باشد؛ در غیر این صورت «—» می‌آید، نه صفر و نه عدد حدسی.
6. **صفر یعنی «داده نداریم»** و دور انداخته می‌شود، نه اینکه «رایگان» تلقی شود.

## متغیرهای محیطی

فایل `.env.example` همهٔ گزینه‌ها را با مقدار پیش‌فرض دارد. حداقل چیزی که لازم است
`TELEGRAM_TOKEN` است.

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `TELEGRAM_TOKEN` | — | **الزامی**؛ توکن ربات از `@BotFather` |
| `RENDER_EXTERNAL_URL` / `WEBHOOK_BASE_URL` | — | دامنهٔ عمومی برای ثبت webhook |
| `WEBHOOK_PATH` | `/tg-webhook` | مسیر دریافت آپدیت‌ها |
| `TELEGRAM_WEBHOOK_SECRET` | `ghematyar-webhook-secret` | هدر محرمانهٔ webhook |
| `PORT` | `10000` | پورت وب‌سرور |
| `ADMIN_IDS` | — | شناسه‌های مجاز به دستورهای مدیریتی |
| `PRICE_CACHE_TTL` | `60` | عمر کش قیمت (ثانیه) |
| `PRICE_STALE_AFTER` | `900` | آستانهٔ «کهنه» شدن (ثانیه) |
| `PRICE_EXPIRE_AFTER` | `3600` | آستانهٔ عدم‌نمایش (ثانیه) |
| `HTTP_TIMEOUT` | `10` | مهلت هر درخواست (ثانیه) |
| `HTTP_MAX_ATTEMPTS` | `3` | تعداد تلاش برای هر درخواست |
| `HTTP_BACKOFF_BASE` / `HTTP_BACKOFF_MAX` | `0.5` / `8` | تأخیر نمایی بین تلاش‌ها |
| `PROVIDER_BREAKER_THRESHOLD` / `PROVIDER_BREAKER_COOLDOWN` | `3` / `120` | تنظیم مدارشکن |
| `HISTORY_RETENTION_DAYS` | `90` | نگهداری تاریخچهٔ قیمت |
| `ALERT_CHECK_INTERVAL` | `120` | فاصلهٔ بررسی هشدارها (ثانیه) |
| `MAX_ALERTS_PER_USER` | `15` | سقف هشدار فعال هر کاربر |
| `ALERT_NOTIFY_COOLDOWN` | `600` | کمینهٔ فاصلهٔ دو اعلان یک هشدار |
| `ALERT_MAX_PER_HOUR` | `10` | سقف اعلان هر کاربر در ساعت |
| `ALERT_DISABLE_AFTER` | `5` | غیرفعال‌سازی خودکار پس از خطای ارسال |
| `GHEMATYAR_DB_PATH` | `./data/ghematyar.db` | مسیر پایگاه داده |
| `GHEMATYAR_DATA_DIR` | `./data` | پوشهٔ داده |
| `GHEMATYAR_ENV` | `development` | `production` رفتار سخت‌گیرانه‌تری دارد |

## اجرای ربات

**Polling — توسعهٔ محلی.** بدون دامنه، بدون SSL و بدون تنظیم webhook. در شروع، هر webhook
ثبت‌شده حذف می‌شود تا آپدیت‌ها گم نشوند:

```bash
python -m ghematyar
```

**Webhook — تولید.** وب‌سرور aiohttp آپدیت‌ها را از تلگرام می‌گیرد:

```bash
export TELEGRAM_TOKEN=123456:ABC-DEF
export WEBHOOK_BASE_URL=https://your-domain.example
python -m ghematyar webhook
```

هر دو حالت پایشگر هشدار را در پس‌زمینه اجرا می‌کنند تا رفتار محصول یکسان باشد.

### نقطه‌های پایانی وب‌سرور

| مسیر | توضیح |
|---|---|
| `POST /tg-webhook` | دریافت آپدیت‌های تلگرام؛ بدون هدر محرمانهٔ درست، کد ۴۰۱ می‌گیرد |
| `GET /health` | سلامت سرویس، وضعیت هر منبع، کش و تاریخچه |
| `GET /` | همان پاسخ، برای بررسی سریع در مرورگر |

> **نکتهٔ فنی مهم:** اپلیکیشن aiohttp یک شیء WSGI یا ASGI نیست، پس زیر gunicorn اجرا
> نمی‌شود. فرمان درست، همان وب‌سرور خود aiohttp است که با `python -m ghematyar webhook`
> بالا می‌آید؛ این فرمان روی همین پروژه آزموده شده و `/health` کد ۲۰۰ می‌دهد.

## دپلوی روی Render

دپلوی این پروژه سه نکتهٔ تعیین‌کننده دارد که اگر رعایت نشوند شکست می‌خورد:

1. **Root Directory الزامی است.** پروژه داخل یک مخزن چندپروژه‌ای (`Demos-FA`) قرار دارد؛ اگر
   Render از ریشهٔ مخزن بیلد کند، `requirements.txt` را پیدا نمی‌کند و build شکست می‌خورد.
2. **فایل blueprint در ریشهٔ مخزن نیست** و در `05-ghematyar-bot/render.yaml` قرار دارد، پس
   هنگام ساخت Blueprint باید مسیر آن صریحاً داده شود.
3. **حالت webhook به دامنهٔ عمومی نیاز دارد.** Render آن را خودش در `RENDER_EXTERNAL_URL`
   می‌گذارد و برنامه در زمان بالا آمدن، webhook را با همان دامنه ثبت می‌کند.

### پیش‌نیاز

- مخزن روی GitHub و دسترسی Render به آن
- توکن ربات: در تلگرام به `@BotFather` پیام دهید، `/newbot` را بزنید و توکنی به شکل
  `123456789:AAE...` بگیرید
- پلن رایگان Render کافی است؛ محدودیت‌های آن پایین‌تر توضیح داده شده

### گام ۱ — ساخت سرویس از Blueprint

1. در داشبورد Render: **New +** → **Blueprint**
2. مخزن `Demos-FA` را انتخاب کنید
3. در فیلد **Blueprint Path** مقدار `05-ghematyar-bot/render.yaml` را وارد کنید
   (Render به‌صورت پیش‌فرض فقط `render.yaml` در ریشهٔ مخزن را می‌بیند)
4. چون `TELEGRAM_TOKEN` با `sync: false` تعریف شده، Render همان‌جا مقدار آن را می‌پرسد؛
   توکن ربات را وارد کنید و **Apply** را بزنید

| Plan | Free |

### گام ۲ — تنظیم متغیرهای محیطی

| متغیر | مقدار |
|---|---|
| `TELEGRAM_TOKEN` | توکن ربات (به‌صورت دستی وارد می‌شود) |
| `TELEGRAM_WEBHOOK_SECRET` | `generateValue` — Render مقدار تصادفی می‌سازد |
| `PYTHON_VERSION` | `3.10.20` |

`TELEGRAM_WEBHOOK_SECRET` نیازی به هم‌خوانی دستی ندارد: برنامه همان مقدار را هنگام
`set_webhook` به تلگرام می‌دهد و درخواست‌های بدون این هدر را با کد ۴۰۱ رد می‌کند.
`PORT` و `RENDER_EXTERNAL_URL` را دستی تنظیم **نکنید**؛ Render خودش تزریق می‌کند.

### گام ۳ — تأیید دپلوی

پس از پایان build، آدرس سرویس به شکل `https://<نام-سرویس>.onrender.com` خواهد بود. سلامت
سرویس را بپرسید:

  "mode": "webhook",

### گام ۴ — پایداری داده (اختیاری، نیازمند پلن پرداختی)

دیسک **پلن رایگان موقتی است**. یعنی پوشهٔ `data/` با هر دپلوی از نو ساخته می‌شود و هشدارها،
دیده‌بان، تاریخچهٔ قیمت و گزارش رویدادها از دست می‌روند. تاریخچهٔ قیمت برای دستور `/chart`
و درصد تغییر هم از صفر شروع می‌شود.

برای نگه‌داشتن داده:

1. سرویس را به یک پلن پرداختی ارتقا دهید (دیسک پایدار روی پلن رایگان قابل اتصال نیست)
2. در زبانهٔ **Disks** دیسکی با نام `ghematyar-data` و مسیر سوارشدن `/var/data` بسازید
   (۱ گیگابایت کافی است)
3. متغیر `GHEMATYAR_DATA_DIR` را برابر `/var/data` بگذارید
4. **Manual Deploy** → **Deploy latest commit**

نمونهٔ این تنظیمات در همان `render.yaml` کامنت شده است.

### نکته‌ها و رفع اشکال

- **فرمان start، gunicorn نیست.** اپلیکیشن aiohttp یک شیء WSGI یا ASGI نیست و زیر gunicorn با
  اولین درخواست خطا می‌دهد (`Application.__call__() takes 1 positional argument but 3 were
  given`). فرمان درست همان وب‌سرور خود aiohttp است.
- **خواب پلن رایگان و ریسک آپدیت تلگرام:** سرویس رایگان پس از حدود ۱۵ دقیقه بی‌فعالیتی خاموش
  می‌شود و بیدار شدنش تا حدود یک دقیقه طول می‌کشد. تلگرام برای تحویل webhook منتظر می‌ماند
  ولی این تأخیر می‌تواند باعث تأخیر یا تکرار تحویل شود. برای رباتی که باید همیشه پاسخ دهد،
  یک پلن پرداختی (یا یک سرویس بیرونی که دوره‌ای به آدرس سلامت درخواست بزند) لازم است.
- **یک نمونه کافی و لازم است:** پایشگر هشدار در همان پروسهٔ وب‌سرور اجرا می‌شود. اگر چند
  نمونهٔ هم‌زمان بالا بیاورید، هر کدام جداگانه پایش می‌کند و یک هشدار چند بار بررسی می‌شود.
- **نسخهٔ Python:** مقدار `PYTHON_VERSION` باید کامل و منتشرشده باشد (مثل `3.10.20`). اگر
  build گفت این نسخه در دسترس نیست، آن را از فهرست پشتیبانی‌شدهٔ Render عوض کنید
  (<https://render.com/docs/python-version>)؛ وابستگی‌های این پروژه روی پایتون ۳٫۱۰ تا ۳٫۱۲
  کار می‌کنند.
- **نمودارها به matplotlib نیاز دارند** که در `requirements.txt` هست. این کتابخانه تنبل
  بارگذاری می‌شود، پس اگر نصب نشود ربات سالم بالا می‌آید و `/chart` صریحاً می‌گوید موتور رسم
  فعال نیست.
- **لاگ‌ها:** در زبانهٔ **Logs** سرویس؛ خطاهای منابع، ثبت webhook و دورهای پایش هشدار همان‌جا
  دیده می‌شوند.

## محدودیت‌ها

- **قیمت‌ها راهنما هستند، نه توصیهٔ معاملاتی.** برای معاملهٔ واقعی از منبع رسمی استفاده کنید.
- **تاریخچه از لحظهٔ نصب جمع می‌شود.** درصد تغییر و نمودار به مشاهده‌های ثبت‌شدهٔ خود ربات
  وابسته‌اند؛ در ساعت‌های اول پس از نصب، نمودار پیام «تاریخچهٔ کافی ندارم» می‌دهد. این رفتار
  عامدانه است: هیچ عددی حدس زده نمی‌شود و خط تخت کشیده نمی‌شود.
- **دقت دسته‌های بازار داخلی** به ساختار خوراک عمومی tgju وابسته است؛ تغییر ساختار آن نیازمند
  به‌روزرسانی پارسر است. تست‌های `test_providers.py` این را پوشش می‌دهند.
- **اجرای محلی روی ویندوز:** اگر بیلد بومی `matplotlib` در محیط شما خراب باشد (سقوط در
  `savefig`)، فقط دستور نمودار در دسترس نخواهد بود. با
  `pip install --force-reinstall matplotlib` یا یک محیط تازه ترمیم می‌شود؛ در دپلوی لینوکسی
  این مشکل وجود ندارد.
- **مقیاس تک‌نمونه‌ای:** پایگاه داده `SQLite` است و پایشگر در همان فرآیند وب‌سرور اجرا می‌شود.
  برای چند نمونهٔ هم‌زمان به یک صف مشترک و پایگاه دادهٔ شبکه‌ای نیاز است.
- **صحت خود اعداد به منبع واگذار شده است.** ربات داده را بازمحاسبه نمی‌کند؛ هر عدد را با ذکر
  منبع و زمان نمایش می‌دهد.
