# قیمت‌یار

![قیمت‌یار](docs/banner.svg)

ربات تلگرام پایش بازار: قیمت لحظه‌ای طلا، سکه، ارز و رمزارز از منابع واقعی،
سیستم هشدار با شرایط قابل‌تعریف، تاریخچهٔ قیمت و رابط کاملاً فارسی.

ساخته‌شده با `aiogram 3`، `aiohttp` و `SQLite`. هیچ قیمتی در کد ثابت نیست؛
هر عددی که به کاربر نشان داده می‌شود از یک منبع زندهٔ بیرونی می‌آید و اگر
منبع در دسترس نباشد، ربات صریحاً همین را می‌گوید.

---

## قابلیت‌ها

- **قیمت زنده** برای ۲۵ قلم در چهار دسته (طلا، سکه، ارز، رمزارز)
- **جستجوی فارسی**: `/price دلار`، `/price سکه امامی`، یا فقط نوشتن «دلار چنده؟»
- **هشدار قیمت** با شرط بالا/پایین رفتن از آستانه، ساخت مرحله‌به‌مرحله یا با یک جمله
- **پایش پس‌زمینه**: هشدارها در فواصل منظم بررسی و در صورت برقرارشدن شرط اعلان می‌شوند
- **تاریخچهٔ قیمت** و دستور `/chart` برای رسم نمودار از داده‌های واقعاً ثبت‌شده
- **دیده‌بان**: فهرست اقلام موردعلاقهٔ هر کاربر با قیمت تازه
- **گزارش رویداد**: `/events` توضیح می‌دهد چرا اعلانی ارسال شد یا نشد
- **وضعیت منابع**: `/status` وضعیت زندهٔ هر منبع، تأخیر پاسخ و مقدار کش را نشان می‌دهد
- **مقاومت در برابر خطای شبکه**: مهلت زمانی، تلاش مجدد با تأخیر نمایی، مدارشکن و تشخیص دادهٔ کهنه

│   │   └── users.py         کاربران

│   │   └── charts.py        رسم نمودار از تاریخچهٔ ثبت‌شده
│   └── bot/
│       ├── handlers/        common، market، alerts، watchlist، fallback
│       ├── middleware.py    ثبت کاربر، مهار سیل، مهار خطا
│       ├── keyboards.py     کیبوردهای inline
│       ├── parsing.py       پارس جمله‌های محاوره‌ای هشدار
│       └── texts.py         متن‌های فارسی
├── tests/                   ۲۳۹ تست + فیکسچرهای ضبط‌شده از پاسخ واقعی منابع

نکتهٔ معماری: **import کردن پکیج هیچ عارضهٔ جانبی ندارد** — نه پایگاه داده
ساخته می‌شود، نه به شبکه می‌رود و نه توکن لازم است. همه‌چیز داخل
`build_services` و `build_runtime` ساخته می‌شود. همین باعث می‌شود برنامه در
یک پروسه چند بار قابل ساخت باشد (تست‌ها، وب‌سرور، جابه‌جایی بین polling و
webhook) و هندلرها به وضعیت import وابسته نباشند.

## منابع داده

| منبع | پوشش | تصدیق‌شده |
|---|---|---|
| `tgju.org` (خوراک ماشین‌خوان) | طلا، سکه، ارز — ۱۴ قلم | تأخیر ~۱٫۷ ثانیه |
| صفحهٔ HTML همان منبع | فقط «سکه گرمی» که در خوراک ماشین‌خوان نیست | آخرین راه |
| `api.coingecko.com` | رمزارز — ۱۱ قلم، همراه تغییر ۲۴ ساعته | تأخیر ~۰٫۷ ثانیه |

انتخاب منابع پیش از پیاده‌سازی بررسی شد: دسترس‌پذیری، ساختار پاسخ، محدودیت
نرخ و رفتار در خطا. دو نکته که در عمل دیده شد:

- خوراک ماشین‌خوان رمزارزها **دلاری** است ولی صفحهٔ HTML همان منبع، تتر را
  **تومانی** نشان می‌دهد. یک قلم با دو واحد در دو مسیر، خطرناک‌تر از نبود
  داده است؛ بنابراین رمزارزهاعامدانه از مسیر HTML کنار گذاشته شده‌اند.
- رمزارزها از یک منبع مستقل (CoinGecko) و نه فقط از tgju خوانده می‌شوند تا
  قطعی یک منبع، کل دسته را از کار نیندازد.

## رفتار دادهٔ زنده

این بخش مهم‌ترین قرارداد پروژه است:

1. **هیچ قیمت ثابت یا ساختگی وجود ندارد.** هیچ مقدار پیش‌فرضی برای قیمت در
   کد نیست. اگر هیچ منبعی داده ندهد، ربات صریحاً می‌گوید داده در دسترس نیست.
   (نسخهٔ قبلی این پروژه در قطعی کامل، از یک فیکسچر آفلاین استفاده می‌کرد و
   قیمت قدیمی را به‌عنوان زنده نشان می‌داد؛ این مسیر کاملاً حذف شده است.)
2. **کش کوتاه‌مدت، ولی برچسب‌دار.** پاسخ‌های پشت‌سرهم از کش سرو می‌شوند
   (`PRICE_CACHE_TTL`، پیش‌فرض ۶۰ ثانیه) و نمایش می‌دهد که از کش آمده است.
3. **سن داده همیشه دیده می‌شود.** هر کارت قیمت، زمان آخرین مشاهدهٔ داده را
   نسبت به حالا می‌نویسد («لحظه‌ای پیش»، «۳ دقیقه پیش»).
4. **کهنه با برچسب، منقضی هرگز.** دادهٔ قدیمی‌تر از `PRICE_STALE_AFTER` با
   وضعیت «کهنه» علامت می‌خورد و قدیمی‌تر از `PRICE_EXPIRE_AFTER` به هیچ
   عنوان نمایش داده نمی‌شود.
5. **تغییر از تاریخچهٔ خودمان.** درصد تغییر فقط وقتی نمایش داده می‌شود که یک
   مشاهدهٔ ثبت‌شدهٔ قبلی وجود داشته باشد؛ در غیر این صورت «—» می‌آید، نه صفر
   و نه عدد حدسی.
6. **صفر یعنی «داده نداریم».** قیمت صفر به‌عنوان «رایگان» تلقی نمی‌شود و
   دور انداخته می‌شود.

مدارشکن: پس از `PROVIDER_BREAKER_THRESHOLD` خطای پیوسته، آن منبع برای
`PROVIDER_BREAKER_COOLDOWN` ثانیه کنار گذاشته می‌شود تا درخواست‌ها معطل نمانند
و به منبع خطاکار فشار نیاید.

## دستورهای ربات

| دستور | کار |
|---|---|
| `/start` | شروع و منوی اصلی |
| `/help` | راهنما |
| `/market` | نمای کلی بازار (اقلام شاخص هر دسته) |
| `/price` | قیمت یک قلم؛ بدون آرگومان، فهرست شاخص‌ها |
| `/gold` `/coins` `/crypto` `/currency` | نمای یک دسته |
| `/chart` | نمودار تاریخچهٔ ثبت‌شده |
| `/alert` | ساخت هشدار (مرحله‌به‌مرحله یا با یک جمله) |
| `/alerts` | فهرست و مدیریت هشدارها (توقف، فعال‌سازی، حذف) |
| `/events` | گزارش رویدادها: چه شد و چرا اعلانی نیامد |
| `/watchlist` | دیده‌بان کاربر |
| `/status` | وضعیت منابع داده، کش و تاریخچه |
| `/about` | دربارهٔ داده‌ها و سلب‌مسئولیت |

**متن آزاد**: «قیمت دلار چنده؟» قیمت را می‌دهد؛ «دلار بالای ۲۵۰۰۰۰» هشدار
می‌سازد؛ «دلار بالای» (بدون عدد) عدد را می‌پرسد. هر سه حالت فارسی محاوره‌ای
را می‌فهمند.

ساخت هشدار شامل جلوگیری از تکرار، سقف تعداد برای هر کاربر، فاصلهٔ زمانی
حداقل بین دو اعلان یک قلم، سقف اعلان ساعتی، حالت یک‌بارمصرف یا تکرارشونده،
وضعیت فعال/متوقف و غیرفعال‌سازی خودکار پس از خطاهای مکرر ارسال است.

## متغیرهای محیطی

فایل `.env.example` همهٔ گزینه‌ها را با مقدار پیش‌فرض دارد.

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `TELEGRAM_TOKEN` | — | **الزامی**؛ توکن ربات از `@BotFather` |
| `RENDER_EXTERNAL_URL` / `WEBHOOK_BASE_URL` | — | دامنهٔ عمومی برای ثبت webhook |
| `WEBHOOK_PATH` | `/tg-webhook` | مسیر دریافت آپدیت‌ها |
| `TELEGRAM_WEBHOOK_SECRET` | `ghematyar-webhook-secret` | هدر محرمانهٔ webhook |
| `PORT` | `10000` | پورت وب‌سرور |
| `ADMIN_IDS` | — | شناسه‌های مجاز به دستورهای مدیریتی |
| `PRICE_CACHE_TTL` | `60` | عمر کش قیمت (ثانیه) |
| `PRICE_STALE_AFTER` | `900` | آستانهٔ «کهنه» شدن (ثانیه) |
| `PRICE_EXPIRE_AFTER` | `3600` | آستانهٔ عدم‌نمایش (ثانیه) |
| `HTTP_TIMEOUT` | `10` | مهلت هر درخواست (ثانیه) |
| `HTTP_MAX_ATTEMPTS` | `3` | تعداد تلاش برای هر درخواست |
| `HTTP_BACKOFF_BASE` / `HTTP_BACKOFF_MAX` | `0.5` / `8` | تأخیر نمایی بین تلاش‌ها |
| `PROVIDER_BREAKER_THRESHOLD` / `PROVIDER_BREAKER_COOLDOWN` | `3` / `120` | تنظیم مدارشکن |
| `HISTORY_RETENTION_DAYS` | `90` | نگهداری تاریخچهٔ قیمت |
| `ALERT_CHECK_INTERVAL` | `120` | فاصلهٔ بررسی هشدارها (ثانیه) |
| `MAX_ALERTS_PER_USER` | `15` | سقف هشدار فعال هر کاربر |
| `ALERT_NOTIFY_COOLDOWN` | `600` | کمینهٔ فاصلهٔ دو اعلان یک هشدار |
| `ALERT_MAX_PER_HOUR` | `10` | سقف اعلان هر کاربر در ساعت |
| `ALERT_DISABLE_AFTER` | `5` | غیرفعال‌سازی خودکار پس از خطای ارسال |
| `GHEMATYAR_DB_PATH` | `./data/ghematyar.db` | مسیر پایگاه داده |
| `GHEMATYAR_DATA_DIR` | `./data` | پوشهٔ داده |
| `GHEMATYAR_ENV` | `development` | `production` رفتار سخت‌گیرانه‌تری دارد |

## اجرای ربات

### Polling — توسعهٔ محلی

بدون دامنه، بدون SSL و بدون تنظیم webhook:

```bash
python -m ghematyar            # یا: python -m ghematyar polling
```

ربات در ابتدا هر webhook ثبت‌شده را حذف می‌کند تا آپدیت‌ها گم نشوند.

### Webhook — تولید

وب‌سرور `aiohttp` آپدیت‌ها را از تلگرام می‌گیرد. برای اجرای محلی:

```bash
export WEBHOOK_BASE_URL=https://your-domain.example
python -m ghematyar webhook
```

نقطه‌های پایانی:

| مسیر | توضیح |
|---|---|
| `POST /tg-webhook` | دریافت آپدیت‌های تلگرام (با هدر `secret_token`) |
| `GET /health` | سلامت سرویس، وضعیت هر منبع، کش و تاریخچه |
| `GET /` | همان پاسخ، برای بررسی سریع در مرورگر |

هر دو حالت، پایشگر هشدار را در پس‌زمینه اجرا می‌کنند تا رفتار محصول یکسان باشد.

## دپلوی روی Render

فایل `render.yaml` آماده است:

```yaml
buildCommand: pip install -r requirements.txt
startCommand: gunicorn webapp:app --workers 1 --threads 4 --bind 0.0.0.0:$PORT
healthCheckPath: /health
```

۱. مخزن را به Render وصل کنید (Blueprint). ۲. مقدار `TELEGRAM_TOKEN` را در
داشبورد وارد کنید. ۳. آدرس عمومی به‌صورت خودکار از `RENDER_EXTERNAL_URL`
خوانده و webhook ثبت می‌شود.

**یک worker** کافی و لازم است: پایشگر هشدار یک بار در هر فرآیند اجرا می‌شود،
پس با چند worker هر کدام جداگانه پایش می‌کردند و یک هشدار چند بار بررسی
می‌شد. `--threads 4` بار هم‌زمانی درخواست‌ها را تأمین می‌کند.

**۲۳۹ تست**، کاملاً آفلاین و بدون نیاز به توکن یا شبکه:

| فایل | پوشش |
|---|---|
| `test_providers.py` | مهلت، تلاش مجدد، تأخیر نمایی، مدارشکن، پاسخ نامعتبر، منبع قطع |
| `test_storage.py` | اسکیما، هشدارها، تاریخچه، دیده‌بان، یکتایی |
| `test_market_service.py` | کش، انقضا، fallback، دادهٔ کهنه، قلم ناشناخته |
| `test_alerts.py` | شرط، تکرارگیریزی، سقف، محدودیت نرخ، یک‌بارمصرف |
| `test_monitor.py` | فعال‌شدن هشدار، مهار سیل، خطای ارسال، منبع قطع |
| `test_handlers.py` | مسیر کامل «آپدیت → فیلتر → هندلر → ارسال» با dispatcher واقعی |
| `test_parsing.py` | پارس جمله‌های محاوره‌ای، واحدها، ارقام فارسی |
| `test_conversion.py` | تبدیل و قالب‌بندی فارسی (علامت، جداکنندهٔ اعشار و هزارگان) |

`tests/fixtures/` از پاسخ واقعی منابع ضبط شده‌اند.

آزمون زنده (نیازمند شبکه) جداگانه اجرا می‌شود: `python -m ghematyar check`.

## محدودیت‌ها

- **قیمت‌ها راهنما هستند، نه توصیهٔ معاملاتی.** برای معاملهٔ واقعی از منبع
  رسمی استفاده کنید.
- **تاریخچه از لحظهٔ نصب جمع می‌شود.** درصد تغییر و نمودار به مشاهده‌های
  ثبت‌شدهٔ خود ربات وابسته‌اند؛ در ساعت‌های اول پس از نصب، نمودار پیام
  «تاریخچهٔ کافی ندارم» می‌دهد. این رفتار عامدانه است: هیچ عددی حدس زده
  نمی‌شود و خط تخت کشیده نمی‌شود.
- **دقت دسته‌های بازار داخلی** به ساختار خوراک عمومی tgju وابسته است؛ تغییر
  ساختار آن نیازمند به‌روزرسانی پارسر است (تست‌های `test_providers.py` این
  را پوشش می‌دهند).
- **نمودارها به `matplotlib` نیاز دارند.** این کتابخانه در کد به‌صورت تنبل
  بارگذاری می‌شود؛ اگر نصب نباشد، ربات سالم بالا می‌آید و `/chart` صریحاً
  می‌گوید موتور رسم فعال نیست، ولی بقیهٔ امکانات کار می‌کنند.
- **اجرای محلی روی ویندوز**: اگر بیلد بومی `matplotlib` در محیط شما خراب
  باشد (سقوط در `savefig`)، فقط دستور نمودار در دسترس نخواهد بود. با
  `pip install --force-reinstall matplotlib` یا محیط تازه ترمیم می‌شود؛ در
  دپلوی لینوکسی این مشکل وجود ندارد.
- **مقیاس تک‌نمونه‌ای**: پایگاه داده `SQLite` است و پایشگر در همان فرآیند
  وب‌سرور اجرا می‌شود. این برای دموی محصول کافی است، ولی برای چند نمونهٔ
  هم‌زمان به یک صف مشترک و پایگاه دادهٔ شبکه‌ای نیاز است.
- **صحت số liệu به منبع واگذار شده است.** ربات داده را بازمحاسبه نمی‌کند؛
