# حس‌سنج — پلتفرم هوش احساسات کامنت فارسی

سامانه‌ای برای تحلیل احساسات نظرات فارسی در سه کلاس **مثبت / خنثی / منفی**؛ از تحلیل یک متن و بارگذاری فایل CSV تا داشبورد تحلیلی، شفافیت مدل و توضیح‌پذیری هر پیش‌بینی. کل زنجیره — نرمال‌سازی، بردارسازی TF-IDF، آموزش، ارزیابی و نمودارها — روی همین سرور اجرا می‌شود: **بدون API بیرونی، بدون مدل زبانی، بدون سرویس ابری**.

> **توجه:** دیتاست این پروژه **سینتتیک** است و از ترکیب قطعه‌جمله‌های نوشته‌شده به‌همراه نویز کنترل‌شده ساخته می‌شود؛ هیچ کامنت واقعی کاربری در آن نیست. اعداد این مخزن معیار کیفیت روی دادهٔ واقعی نیستند و نباید به‌عنوان آن خوانده شوند. این محدودیت در خود رابط، در پابرگ همهٔ صفحه‌ها و در خروجی API هم اعلام می‌شود.

## اجرای محلی

```bash
cd 09-hassanj-fa-sentiment
python -m pip install -r requirements.txt

# ساخت دیتاست + آموزش مدل (یک بار؛ حدود یک دقیقه)
python -c "from hassanj.model import train_all; train_all()"

# اجرای سرور توسعه
python app.py          # یا: python -m hassanj
# سپس در مرورگر: http://127.0.0.1:5000
```

نیازمندی: پایتون ۳٫۱۰ یا بالاتر. اگر پوشهٔ `models/` خالی باشد، سرویس در نخستین درخواست خودش آموزش می‌دهد — کندتر، ولی بدون خطا.

## API

همهٔ پاسخ‌ها یک پوشش یکدست دارند: `{"ok": true, "data": …}` یا `{"ok": false, "error": …}`. کدهای برچسب در API لاتین می‌مانند (`pos` / `neu` / `neg`) و نگاشت فارسی فقط در رابط انجام می‌شود.

| متد | مسیر | توضیح |
|---|---|---|
| `GET` | `/health` | وضعیت سرویس، مدل انتخاب‌شده، شمار نمونه‌ها، برچسب‌ها |
| `POST` | `/api/analyze` | تحلیل یک متن — JSON (`{"text": "…"}`) یا `form` (`text=…`) |
| `GET` | `/api/metrics` | معیارهای درون‌توزیع، بیرون‌از‌توزیع و اعتبارسنجی متقابل |
| `GET` | `/api/mix` | ترکیب واقعی، ترکیب پیش‌بینی‌شده و مقایسهٔ آن دو |
| `GET` | `/api/terms?label=pos` | واژگان متمایزکنندهٔ یک کلاس |
| `GET` | `/api/trend` | سهم کلاس‌ها به تفکیک ماه |
| `GET` | `/api/model-status` | وجود و حجم فایل مدل |

```bash
curl -s -X POST http://127.0.0.1:5000/api/analyze \
  -H "Content-Type: application/json" \
  -d '{"text": "کیفیت عالی بود و ارسال سریع"}'
```

## مدل و معیارها

سه طبقه‌بند روی یک بردارسازی مشترک (TF-IDF با بازهٔ یک و دو واژه‌ای) آموزش می‌بینند و برنده با F1 آزمون هم‌توزیع انتخاب می‌شود.

| مدل | F1 آزمون | F1 دست‌نویس | فاصله | زمان آموزش |
|---|---|---|---|---|
| MultinomialNB | ۰٫۹۶۴ | ۰٫۷۰۷ | ۰٫۲۵۷ | ۰٫۱۰ ثانیه |
| **LinearSVM (کالیبره)** | **۰٫۹۸۹** | **۰٫۷۵۰** | ۰٫۲۳۹ | ۰٫۱۹ ثانیه |
| LogisticRegression | ۰٫۹۸۶ | ۰٫۷۲۲ | ۰٫۲۶۴ | ۰٫۱۵ ثانیه |

- **آزمون هم‌توزیع:** ۳۶۰ نمونه از همان دیتاست قالب‌محور. این عدد **خوش‌بینانه** است، چون واژه‌های آزمون تقریباً همان واژه‌های آموزش‌اند.
- **آزمون دست‌نویس:** ۷۲ جملهٔ کامل و طبیعی که هیچ‌کدام در آموزش نبوده‌اند. این عدد پایین‌تر است و **همان چیزی است که باید معیار گرفت**.
- **اعتبارسنجی متقابل:** ۰٫۹۹ با انحراف معیار ۰٫۰۰۲۲ روی کل داده.
- اندازهٔ واژگان: ۱۴۰۴ ویژگی TF-IDF.

ستون «فاصله» تفاوت دو آزمون است و عمداً نمایش داده می‌شود: مدل روی دادهٔ هم‌شکل با آموزش خوب کار می‌کند و روی زبان واقعی کمتر. همین فاصله، دلیل وجود نشانگر «پوشش واژگان» در صفحهٔ تحلیل متن است.

## خط لولهٔ NLP

| مرحله | کار |
|---|---|
| نشانی و منشن | حذف پیش از هر چیز، تا ایموجی چسبیده به آن‌ها از دست نرود |
| صفحه‌کلید عربی | `ي` `ى` → `ی` · `ك` → `ک` · `ة` → `ه` (۴ نگاشت) |
| اعراب | حذف کامل |
| ایموجی | ۳۰ ایموجی احساسی به واژهٔ فارسی نگاشته می‌شود (`❤️` → «عالی»، `😡` → «بد») |
| تکرار حرف | سه تکرار یا بیشتر → یکی، **فقط در خط فارسی** |
| غلط تایپی | ۱۲ غلط پرتکرار اصلاح می‌شود |
| علائم | حذف؛ نیم‌فاصله حفظ می‌شود و در توکن‌سازی شکسته می‌شود |
| ایستاها | ۷۰ ایستای فارسی حذف می‌شود، ولی نشانهٔ نفی می‌ماند |
| نفی | توکن زیر نفی با پیشوند `نـ` علامت می‌خورد تا «ناراحت شدم» و «ناراحت نشدم» یک بردار نگیرند |

## توضیح‌پذیری و صداقت پاسخ

مدل همیشه برچسب نمی‌دهد؛ وضعیت ورودی پیش از هر عددی گزارش می‌شود:

| وضعیت | معنی | رفتار |
|---|---|---|
| `empty` | متن خالی | برچسبی گزارش نمی‌شود |
| `no_signal` | هیچ توکن معناداری ندارد | برچسبی گزارش نمی‌شود |
| `out_of_domain` | هیچ واژه‌ای در واژگان مدل نیست (مثلاً متن انگلیسی) | برچسبی گزارش نمی‌شود |
| `thin_coverage` | کمتر از نیمی از واژه‌ها در واژگان هست | نتیجه با هشدار گزارش می‌شود |
| `ok` | پوشش کافی | نتیجه با باند «قابل اتکا / مرزی / نامطمئن» |

برای هر متن، سهم هر واژه در جهت یا خلاف برچسب گزارش می‌شود. این عدد **احتمال نیست** و در رابط هم همین‌طور نوشته شده؛ یک امتیاز نسبی است برای مقایسهٔ واژه‌ها با هم.

## ویژگی‌های پیاده‌سازی

- **بدون وابستگی سنگین:** Flask + scikit-learn + pandas. هیچ کتابخانهٔ نمودار، هیچ فریم‌ورک فرانت‌اند و هیچ فونت اینترنتی در کار نیست.
- **نمودارهای SVG سمت سرور:** صفحهٔ تحلیل بدون یک بایت JavaScript اضافه و بدون درخواست شبکه‌ای برای دادهٔ نمودار رندر می‌شود. سه قاعده در `hassanj/charts.py` رعایت و آزموده شده است: سقف محور هرگز زیر بزرگ‌ترین داده نمی‌افتد، لنگر متن آگاه به جهت است (بوم SVG داخل سند راست‌به‌چپ معنای `text-anchor` را آینه می‌کند)، و حاشیهٔ محور از پهنای واقعی برچسب حساب می‌شود.
- **تحلیل زنده به‌صورت بهبود تدریجی:** با غیرفعال بودن JavaScript، فرم تحلیل متن و فرم بارگذاری فایل هر دو با ارسال معمولی کار می‌کنند؛ با فعال بودن، نتیجه بدون بارگذاری صفحه به‌روز می‌شود و متن در نشانی صفحه می‌ماند تا قابل اشتراک باشد.
- **رقم فارسی در سراسر رابط:** هر عددی که کاربر می‌خواند از `hassanj/labels.py` می‌گذرد (ممیز `٫`، جداکنندهٔ هزارگان `٬`). آزمون خودکار روی همهٔ صفحه‌ها نگهبانی می‌دهد.
- **خودترمیمی مدل:** فایل joblib نسخهٔ `scikit-learn` خودش را ثبت می‌کند. اگر نسخه عوض شود یا فایل خراب باشد، مدل کنار گذاشته و از نو ساخته می‌شود — یک بار آموزش چند ثانیه‌ای، بهتر از خطای ۵۰۰ روی همهٔ صفحه‌ها.
- **روند قابل بازرسی:** ترکیب ماهانهٔ کلاس‌ها از یک تابع بیرون می‌آید که هم اعلان و هم اندازه‌گیری از آن تغذیه می‌شوند؛ جدول صفحهٔ متدولوژی این دو را کنار هم نشان می‌دهد تا تطابقشان دیده شود.
- **خروجی اکسل‌پسند:** CSV با BOM یوتی‌اف-۸ و نام فایل درصدگذاری‌شده به شکل RFC 5987 صادر می‌شود تا هم اکسل ویندوزی متن فارسی را درست بخواند و هم پاسخ روی سرور واقعی نشکند.

## دیتاست

- ۱۸۰۰ نمونه، دقیقاً ۶۰۰ در هر کلاس — توازن عمدی تا مدل به کلاس پرتعداد کج نشود.
- ساخته‌شده از ۱۰۸ قطعه‌جمله (۳۹ مثبت، ۳۷ منفی، ۳۲ خنثی) که با سه تا پنج قطعه ترکیب می‌شوند.
- ۲۵٪ نمونه‌ها یک قطعهٔ مقابل هم دارند («خوب بود ولی گرون») تا ابهام واقعی در آموزش حاضر باشد.
- ده‌ها نمونه واژهٔ انگلیسی دارند تا متن مخلوط فارسی/انگلیسی در دیتاست دیده شود.
- ستون تاریخ با پنجرهٔ ثابت شش‌ماهه؛ سهم کلاس‌ها ماه‌به‌ماه تغییر می‌کند و روند از جدول صریح `MIX_BY_MONTH` می‌آید.
- نویز از همان جدول‌های نرمال‌ساز تزریق می‌شود (حروف عربی و غلط‌های تایپی)، پس مدل روی همان چیزی تمرین می‌کند که در زمان اجرا اصلاح می‌شود — یک منبع حقیقت، نه دو تا.

## دپلوی روی Render

فایل `render.yaml` در ریشهٔ همین پوشه آماده است؛ دیتاست و مدل **در مخزن نیستند** و در زمان ساخت تولید می‌شوند.

### روش ۱ — Blueprint (پیشنهادی)

1. پوشهٔ `09-hassanj-fa-sentiment` را در مخزن گیت‌هاب خود پوش کنید.
2. در داشبورد Render: **New → Blueprint** و انتخاب همان مخزن.
3. Render فایل `render.yaml` را می‌خواند و سرویس را می‌سازد. مقدار `rootDir` روی `09-hassanj-fa-sentiment` تنظیم شده، پس لازم نیست مخزن را جدا کنید.
4. **Apply** را بزنید. نخستین ساخت چند دقیقه طول می‌کشد چون مدل همان‌جا آموزش می‌بیند.

### روش ۲ — سرویس دستی

اگر سرویس را دستی می‌سازید، این مقادیر را دقیقاً وارد کنید:

| فیلد | مقدار |
|---|---|
| Language / Runtime | Python 3 |
| Root Directory | `09-hassanj-fa-sentiment` |
| Build Command | `pip install -r requirements.txt && python -c "from hassanj.model import train_all; train_all()"` |
| Start Command | `gunicorn wsgi:application --bind 0.0.0.0:$PORT --workers 1 --threads 4 --timeout 120` |
| Health Check Path | `/api/health` |

### متغیرهای محیطی

| کلید | مقدار | کاربرد |
|---|---|---|
| `PYTHON_VERSION` | `3.11.9` | نسخهٔ پایتون ساخت |
| `PYTHONUNBUFFERED` | `1` | ثبت بی‌درنگ لاگ‌ها |
| `HASSANJ_WARM_MODEL` | `1` (پیش‌فرض) | گرم‌کردن مدل در زمان بالا آمدن کارگر |
| `PORT` | خودکار | پورت سرویس |

### نکته‌های عملیاتی

- **زمان ساخت:** مرحلهٔ `train_all` سه نامزد را آموزش می‌دهد و اعتبارسنجی متقابل ۵ تایی اجرا می‌کند؛ روی پلن رایگان حدود یک تا دو دقیقه می‌گیرد. اگر خطای زمان ساخت خوردید، `-HASSANJ_WARM_MODEL` را همیشه روشن بگذارید و مقدار `Health Check Path` را دست نزنید.
- **گرم‌کردن مدل:** `wsgi.py` مدل را پیش از نخستین درخواست از دیسک می‌خواند (اندازه‌گیری محلی: حدود ۲٫۶ ثانیه). این کار از کندی نخستین بازدیدکننده جلوگیری می‌کند، ولی سرعت خودِ بالا آمدن سرویس را کمی کم می‌کند؛ در عوض هر بازدید بعدی سریع است.
- **بار سرد روی پلن رایگان:** سرویس رایگان پس از بی‌کاری خواب می‌رود و نخستین درخواست بعدی باید منتظر بالا آمدن کانتینر بماند. برای نمایش به کارفرما، چند دقیقه پیش از جلسه یک درخواست به `/api/health` بزنید یا پلن را یک درجه بالاتر ببرید.
- **تعداد کارگرها:** روی یک کارگر تنظیم شده چون هر کارگر نسخهٔ خودش از مدل را در حافظه نگه می‌دارد. افزایش `--workers` ظرفیت هم‌زمانی را بالا می‌برد و حافظه را چند برابر می‌کند.
- **پایداری داده:** سرویس هیچ پایگاه داده‌ای ندارد؛ تنها حالت ماندگار، فایل‌های ساخته‌شده در زمان build است. هیچ چیزی برای پشتیبان‌گیری وجود ندارد.
- **بازنشر خودکار:** با هر پوش روی شاخهٔ اصلی، Render ساخت را تکرار می‌کند و مدل با همان seed از نو ساخته می‌شود؛ پس اعداد گزارش‌شده بین دو دپلوی تغییر نمی‌کنند.

- **طنز و کنایه را نمی‌فهمد.** «عجب کیفیتی داشت!» احتمالاً مثبت خوانده می‌شود.
- **نفی مرکب را نصفه می‌گیرد.** نشانه‌گذاری نفی کمک می‌کند، ولی جمله‌های چندلایه هنوز خطا دارند.
- **متن انگلیسی را نمی‌پوشاند.** واژگان مدل فارسی است؛ جملهٔ کامل انگلیسی بیرون از دامنه اعلام می‌شود، نه این‌که حدس زده شود.
- **روی دامنهٔ تازه آموزش ندیده.** اگر کامنت‌ها از حوزهٔ دیگری باشند (پزشکی، مالی)، دقت افت می‌کند.
- **داده سینتتیک است.** عددهای این سرویس معیار کیفیت روی کامنت واقعی نیستند. برای استفادهٔ واقعی، گام نخست جایگزینی `hassanj/dataset.py` با کامنت برچسب‌خوردهٔ خودتان و دوباره اجرا کردن `train_all` است؛ بقیهٔ سامانه تغییری لازم ندارد.
