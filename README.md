## دربارهٔ این مخزن

هر پوشه یک محصول مستقل با README کامل خودش است: روش کار، معماری، مراحل اجرا، متغیرهای محیطی، تنظیمات استقرار و محدودیت‌های اعلام‌شده. این مخزن چندپروژه‌ای است و پروژه‌ها به هم وابسته نیستند؛ هر کدام وابستگی‌ها، پایگاه داده و تنظیمات استقرار خودش را دارد.

هدف این مجموعه نمایش توان ساخت **سیستم‌های واقعی** است، نه نمونه‌های نمایشی سطحی. به همین دلیل هر پروژه سه چیز دارد که در یک دمو ساده معمولاً غایب است: آزمون خودکار برای مسیرهای اصلی، مدیریت خطای نوع‌دار با پیام کاربرپسند، و اعلام صریح محدودیت‌ها در همان رابط کاربری.

## اصول مهندسی مشترک

این اصول در همهٔ پروژه‌ها به‌صورت یکسان رعایت شده و علت شباهت ساختاری آن‌ها همین است:

- **جداسازی لایه‌ها.** هیچ صفحه‌ای مستقیم با پایگاه داده یا pandas کار نمی‌کند و هیچ لایهٔ تحلیلی HTML نمی‌سازد. مسیر داده یک‌طرفه است.
- **تک‌منبع حقیقت.** آستانه‌ها، وزن‌ها، سقف‌ها و پالت‌ها در یک ماژول تنظیمات می‌نشینند؛ رابط و موتور همیشه یک عدد واحد می‌گویند.
- **خطای نوع‌دار با پیام انسانی.** خطاها کد و پیام مشخص دارند و متن آن‌ها برای کاربر نهایی نوشته شده، نه برای لاگ. جزئیات فنی در لاگ سرور می‌ماند.
- **آزمون روی داده و مرورگر واقعی.** آزمون‌ها با فایل‌های شکسته، کدگذاری‌های مختلف، ورودی خالی و قالب‌های پشتیبانی‌نشده هم سنجیده می‌شوند.
- **رقم فارسی در سراسر رابط.** هر عددی که کاربر می‌خواند از یک ماژول قالب‌بندی می‌گذرد، و آزمون خودکار جلوی نشت رقم لاتین را می‌گیرد.
- **بدون وابستگی سنگین.** نمودارها SVG سمت سرور هستند و در سه پروژهٔ داده‌محور هیچ کتابخانهٔ نمودار یا فونت اینترنتی در مرورگر بار نمی‌شود.
- **احترام به `prefers-reduced-motion` و کارکرد بدون JavaScript.** فرم‌ها و مسیرهای اصلی بدون اسکریپت هم کار می‌کنند.

## استقرار روی Render

این مخزن چندپروژه‌ای است و **ریشهٔ انتشار باید در هر سرویس مشخص شود**، وگرنه Render از ریشهٔ مخزن منتشر می‌کند و وابستگی‌ها را پیدا نمی‌کند.

### سایت‌های ایستا (۱، ۲، ۳)

**New +** → **Static Site**؛ سپس:

| فیلد | مقدار |
|---|---|
| Repository | همین مخزن |
| Root Directory | مثلاً `02-arman-holding` |
| Build Command | خالی |
| Publish Directory | `.` |

### سرویس‌های وب (۴ تا ۱۰)

هر پروژه یک `render.yaml` در ریشهٔ خودش دارد. **New +** → **Blueprint** → انتخاب مخزن → و در فیلد **Blueprint Path** مسیر همان فایل، مثلاً `10-report-saz/render.yaml`. برای ساخت دستی هم کافی است **Root Directory** روی نام پوشه تنظیم شود و **Build** و **Start Command** از جدول README همان پروژه برداشته شود.

دو نکته که روی پلن رایگان به کار می‌آید:

- سرویس پس از بی‌کاری خواب می‌رود و بیداری نخست حدود یک دقیقه طول می‌کشد؛ `healthCheckPath` در هر `render.yaml` تنظیم شده تا سنجش وضعیت ممکن باشد.
- دیسک سرور موقت است. پروژه‌هایی که داده را روی دیسک نگه می‌دارند، پس از هر ری‌استارت آن را از دست می‌دهند؛ این در README هر پروژه نوشته شده است.

## آزمون‌ها

```bash
cd 09-hassanj-fa-sentiment
pip install -r requirements-dev.txt
pytest -q
```

مجموع **۱٬۷۲۸ آزمون** در هفت پروژهٔ پایتون: ۱۴۹ + ۲۳۹ + ۱۸۹ + ۲۷۳ + ۳۰۰ + ۲۴۷ + ۳۳۱.

آزمون‌ها آفلاین‌اند. پروژه‌هایی که به شبکه وابسته‌اند (۵، ۶، ۷) پاسخ واقعی منابع را یک‌بار ضبط و در `tests/fixtures/` نگه‌داری می‌کنند، پس آزمون‌ها نه به اتصال اینترنت وابسته‌اند و نه به نرخ لحظه‌ای بازار. پروژه‌های ۸ و ۹ دیتاست و مدل را در پوشهٔ موقت می‌سازند و به فایل‌های واقعی پروژه دست نمی‌زنند.

## شفافیت داده

سه پروژه با داده‌ای کار می‌کنند که **ساختگی** است و این موضوع هم در رابط کاربری و هم در README آن‌ها اعلام شده است:

- **۸ خانه‌یاب** — دیتاست مسکن با یک مدل قیمت صریح و seed ثابت ساخته می‌شود و قیمت‌ها نرخ واقعی بازار نیستند. هشدار در سرصفحهٔ برنامه و صفحهٔ متدولوژی دیده می‌شود.
- **۹ حس‌سنج** — دیتاست از ترکیب قطعه‌جمله‌های نوشته‌شده با نویز کنترل‌شده ساخته می‌شود و هیچ کامنت واقعی کاربری در آن نیست. تفاوت معیار روی دادهٔ قالب‌محور و جمله‌های طبیعی دست‌نویس، در همان صفحهٔ مدل کنار هم نمایش داده می‌شود.
- **۱۰ گزارش‌ساز** — مجموعهٔ نمونهٔ قابل دانلود ساختگی است و این در نام فایل و برگهٔ «درباره این داده» همان کارپوشه نوشته شده است.

پروژه‌های ۵، ۶ و ۷ برعکس، با دادهٔ **زندهٔ واقعی** از منابع عمومی کار می‌کنند؛ محدودیت‌های همان منابع (تأخیر، تفاوت با نرخ رسمی، قطع سرویس) در README خودشان فهرست شده است.
